## Side-by-side installation fix

All admitted public patches now require the package-rename resource patch as a
shared dependency. The rename runs during resource finalization and changes the
manifest package and known package-derived provider/permission authorities. If the
public Package Rename option was not chosen, the fallback app label is **Gboard Mod**.
If it was chosen, its custom app name is preserved by the later shared finalizer.

The resulting target package is `dev.jason.com.google.android.inputmethod.latin`,
not `com.google.android.inputmethod.latin`. Recompile the `.mpp` and re-patch from
the supported original source. Before attempting installation, verify the output
package ID with an APK inspector. Full/split assembly and on-device behavior are
still unverified: a renamed base plus unchanged-package splits will not form a
valid install set. Do not remove the preinstalled keyboard to work around a
signature mismatch.

## Local validation and build

Python 3 and JDK 21 are required. Full builds also require Android SDK, Gradle/Maven downloads, and credentials for the Morphe GitHub Packages registry.

Run from the repository root:

```bash
python3 tools/port1846/verify_port.py
python3 tools/port1846/verify_port.py /path/to/original.apkm --java-tests --report port-18.4.6/rechecked.json
bash ./gradlew :patches:test --tests "dev.jason.gboardpatches.tools.bindings.*" --no-daemon
bash ./gradlew :patches:buildAndroid :patches:generatePatchesList -x test --no-daemon
```

The build command omits remaining upstream test suites because they contain contracts for other Gboard versions. The preceding test command covers the binding compiler and the new partial port admission; these tests have not run in this workspace. This is not a full test-suite pass.

The workflow generates an `.mpp` only if compilation, selected tests, wiring verification and packaging succeed. It does not test application of the bundle to your APKM. Import the built bundle locally in Morphe and use the complete split APKM. Do not treat `base.apk` alone as a verified installable package.

When testing, confirm patch application succeeds, then install and exercise each selected feature on Android.

`changes.patch` records edits to upstream text files. New port files are under `port-18.4.6`, `tools/port1846`, and `Port1846BuildContractTest.kt`.

## Revision 4.0.0-port1846.2

Added nine features to the prior 25-feature source port:
Custom Theme, G Logo on Spacebar, Zhuyin Bottom Row Key Sizes, Zhuyin Slide Input,
Swipeable Custom Top Row, Emojis/stickers/GIFs Tab Order, Toolbar Editing Buttons,
Floating Web Search, and Split Keyboard. All nine still need Morphe application
and Android device tests.

The typed runtime contract matters: in this APK, SoftKeyDef uses `f:ActionDef[]`,
`g:CharSequence[]` and `h:int[]`; ActionDef uses `c:pti` and `d:pue[]`. Adapters now
read these fields and bridge arrays to the existing policy code. The old field
names could resolve successfully while returning completely different data.
The SoftKey bind contract also has one normal return, rather than the upstream
two-return shape; its exception handler is retained.

The standalone Java check is a limited compilation and regression test. It does
not compile Android-dependent classes or Kotlin patches. The full Gradle build
remains blocked here by unavailable dependency downloads.
